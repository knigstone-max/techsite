# מדריך ניהול האתר (CMS)

האתר מנוהל דרך **Pages CMS**, מערכת ניהול חינמית שעובדת ישירות מול המאגר ב-GitHub. כל שמירה נשמרת כ-commit ב-`main`, והאתר מתעדכן לבד תוך 2-3 דקות. אין שרת, אין תשלום.

## כניסה בפעם הראשונה (המנהל)

1. נכנסים ל-https://app.pagescms.org ולוחצים **Sign in with GitHub**.
2. מתחברים עם חשבון ה-GitHub `knigstone-max` (הבעלים של האתר = המנהל).
3. בפעם הראשונה GitHub יבקש להתקין את האפליקציה של Pages CMS. בוחרים **Only select repositories**, מסמנים את `techsite`, ומאשרים (חינם).
4. בוחרים את `knigstone-max/techsite`, ענף `main`. בתפריט הצד יופיעו **כתבות בעברית** ו-**English posts**, וגם **Media** לתמונות.

קישור ישיר אחרי ההתקנה: https://app.pagescms.org/knigstone-max/techsite/main

## עריכת כתבה

פותחים את הכתבה מהרשימה, משנים, ולוחצים **Save**. זהו.

## הוספת כתבה

1. **כתבות בעברית** ← **Add an entry**.
2. ממלאים: כותרת, `slug` (אותיות לועזיות קטנות, ספרות ומקפים, למשל `galaxy-s27-review`), תאריך, קטגוריה, תקציר.
3. תמונה ראשית: מעלים או בוחרים מהמדיה. אם יש תמונה, חובה למלא גם **תיאור התמונה** ו**קרדיט**. בלי תמונה האתר ישים את איור הקטגוריה.
4. כותבים את התוכן ושומרים.
5. לגרסה האנגלית: אותו דבר ב-**English posts**, עם **אותו slug בדיוק**, כדי שהכתבות יקושרו זו לזו.

### כתיבת תוכן (Markdown)

- `## כותרת משנה`
- `- פריט ברשימה`
- `**מודגש**`, `[טקסט קישור](https://...)`
- תמונה בתוך הכתבה: קודם מעלים אותה ב-**Media**, ואז כותבים בשורה נפרדת:
  `![תיאור התמונה](img/posts/שם-הקובץ.webp "כיתוב מתחת לתמונה")`
- תיבת ציון בביקורת:
  ```
  :::score
  ## השורה התחתונה

  9/10

  משפט סיכום.
  :::
  ```
- בביקורות שלנו משאירים את **מקורות** ריק.

## הסתרה או מחיקה של כתבה

- **הסתרה זמנית**: מסמנים **טיוטה** ושומרים. הכתבה נשארת במערכת אבל לא מופיעה באתר.
- **מחיקה**: ברשימת הכתבות, בתפריט של הכתבה ← **Delete**. אפשר לשחזר כל מחיקה מהיסטוריית ה-commits ב-GitHub.

## הוספת כותבים ועורכים

המנהל (רק חשבון GitHub עם גישה למאגר) מזמין כותבים, **בלי שהם צריכים חשבון GitHub**:

1. נכנסים ל-https://app.pagescms.org/knigstone-max/techsite/main/collaborators (או **Collaborators** בתפריט הצד).
2. מקלידים את המייל של הכותב ולוחצים **Invite**.
3. הכותב מקבל מייל עם קישור, ובכניסות הבאות נכנס ב-https://app.pagescms.org/sign-in עם המייל שלו (קוד חד-פעמי למייל).
4. להסרת כותב: באותו מסך, מוחקים אותו מהרשימה.

### מה כל אחד יכול לעשות

| תפקיד | איך נכנס | מה מותר |
| --- | --- | --- |
| **מנהל** (`knigstone-max`) | GitHub | הכל: כתבות, תמונות, הזמנת והסרת כותבים, הגדרות ה-CMS (`.pages.yml`) |
| **כותב/עורך** (הוזמן במייל) | מייל + קוד | לכתוב, לערוך, למחוק כתבות ולהעלות תמונות. לא יכול להזמין אנשים או לשנות הגדרות |
| **חבר צוות עם GitHub** (אופציונלי) | GitHub | אם מוסיפים אותו ב-GitHub ← Settings ← Collaborators, יש לו גישת כתיבה מלאה למאגר, כולל קוד. מומלץ רק למי שסומכים עליו לגמרי |

### מגבלות שכדאי לדעת

- **אין שלב אישור**: כל שמירה של כותב מתפרסמת מיד. אין כרגע הפרדה בין "כותב" ל"עורך" ב-Pages CMS (הרשאות מפורטות מסומנות אצלם כ"בקרוב"). מי שרוצה בקרה יכול לבקש מהכותבים לשמור כ**טיוטה**, והמנהל מוריד את הסימון כשהכתבה מאושרת.
- כל כותב שהוזמן יכול גם למחוק כתבות. כל שינוי נשמר בהיסטוריה של GitHub, כך שאפשר לשחזר.
- בשורת ה-commit מופיע שם הכותב, כך שרואים מי שינה מה.
- אם מוסיפים קטגוריה חדשה ב-`site.json`, צריך להוסיף אותה גם לרשימת הקטגוריות ב-`.pages.yml`.
- אם שמירה נכשלת בבנייה (למשל תמונה בלי תיאור), האתר הקודם נשאר באוויר. רואים את השגיאה ב-GitHub ← Actions.
